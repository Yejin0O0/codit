# 프론트엔드 백엔드 API 연동 PRD

## 1. 개요

익스텐션 위젯과 익스텐션 페이지의 목 데이터를 실제 백엔드 API로 교체한다.
이슈 #60의 완료 조건에 따라 모든 API 호출은 `authenticatedFetch`를 사용한다.

## 2. 사용자 스토리

- 위젯에서 저장 버튼을 누르면 결과 기록이 실제 DB에 저장된다
- 태그 선택 화면에 진입하면 실제 태그 목록이 서버에서 로드된다
- 커스텀 태그를 추가하면 서버에 등록된다
- 익스텐션 페이지 히스토리 탭에서 실제 풀이 기록을 확인할 수 있다

## 3. 기술 결정

### ADR-1. API 호출 구조 — 커스텀 훅 분리

**Context**
목 데이터를 실제 API로 교체할 때 API 호출 로직과 상태(loading/error/data)를 어디에 둘지 결정해야 한다. App.tsx에 직접 넣거나, 커스텀 훅으로 분리하거나, 순수 함수 서비스 레이어로 분리하는 3가지 안을 검토했다.

**Decision**
커스텀 훅 분리를 채택한다. `useSaveAttempt`, `useTags`, `useProblemHistory` 훅을 신규 생성해 API 호출, 로딩/에러 상태, 토스트 트리거를 훅 안에 캡슐화한다. App.tsx는 훅의 반환값만 사용한다.

**Alternatives**
- **App.tsx 직접 호출 기각** — App.tsx가 이미 화면 전환·타이머·위젯 위치 등 다양한 책임을 가지고 있어 API 상태까지 추가하면 단일 책임 원칙이 무너지고 테스트 경계가 불명확해진다.
- **API 서비스 레이어 기각** — 순수 함수 레이어를 별도로 두면 상태 관리 위치가 애매해지고, 훅도 추가로 필요해져 파일 수만 늘어난다. 현 규모에서는 오버엔지니어링이다.

**Consequences**
- (+) `useAuth`, `useProblemHistory` 등 기존 훅 패턴과 일관성 유지
- (+) 훅 단위로 독립 테스트 가능 — API mock을 훅 테스트에만 집중
- (+) App.tsx는 훅 반환값만 받아 화면 렌더링에 집중 가능
- (-) 훅 파일 3개 신규 추가 (useSaveAttempt, useTags, useProblemHistory)

### ADR-2. 저장 실패 UX — 토스트 + 경고 아이콘

**Context**
저장 API 호출 실패 시 사용자에게 어떻게 알리고 재시도 경로를 제공할지 결정해야 한다.

**Decision**
shadcn 토스트로 실패를 즉시 알리고, 저장 버튼에 경고 아이콘을 추가해 토스트가 사라진 후에도 에러 상태를 유지한다. 버튼 텍스트는 변경하지 않으며, 재클릭 시 API를 재시도한다.

**Alternatives**
- **토스트만 (자동 닫힘) 기각** — 토스트가 사라지면 에러 상태가 없어져 사용자가 저장이 안 됐다는 걸 인지하지 못할 수 있다.
- **인라인 에러 텍스트 기각** — 버튼 주변 레이아웃 변경이 필요하고, 현재 위젯 공간이 좁아 UI가 어색해질 수 있다.
- **silent fail 기각** — 데이터 유실을 사용자가 알 수 없어 위험하다.

**Consequences**
- (+) 즉각적인 피드백(토스트) + 지속적인 상태 표시(아이콘)를 동시에 제공
- (+) 버튼 재클릭으로 재시도가 자연스럽게 연결됨
- (-) shadcn Toast 컴포넌트 초기 설치 필요 (1회성 작업)

## 4. Out of Scope

- 오프라인 저장 / 큐잉
- 저장 이력 로컬 캐싱
- 히스토리 필터링 / 검색
- 태그 삭제 / 수정

## 5. 용어 정의

| 용어 | 정의 |
|------|------|
| 결과 기록 (Attempt) | 문제 풀이 1회의 결과 — 결과(CORRECT/WRONG/HOLD), 시간, 태그, 메모 포함 |
| 태그 (Tag) | 문제에 붙이는 알고리즘 유형 레이블. 코어 태그(서버 정의)와 커스텀 태그(사용자 정의)로 구분 |
| 히스토리 (Problem History) | 사용자가 풀었던 문제의 결과 기록 목록 |
| authenticatedFetch | 선제 refresh + 401 fallback이 내장된 인증 fetch 래퍼 |
