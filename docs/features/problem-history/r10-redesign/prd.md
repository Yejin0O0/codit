# 문제 상세(회차 히스토리) 재설계 — PRD (리디자인 브리프)

> Layer 2 R10. 에픽 #51 / 이슈 #102. base = R9(#100) 위 스택.
> `AttemptTimeline` **레이아웃**만 재설계 — `AttemptItem`은 그대로 재사용.

## 배경

기존 `AttemptTimeline`은 모든 회차를 `border-t`로만 나눈 세로 리스트였다 — "히스토리"라는
화면 이름에 비해 회차 간 시간 흐름·이동이 잘 안 읽혔다. 회차가 많아질수록(예: 여러 번
재도전한 문제) 스크롤이 길어지고 특정 회차를 찾기 어려웠다.

## 사용자 스토리

- **US-1** 여러 번 시도한 문제에서 특정 회차를 빠르게 찾아 볼 수 있다.
- **US-2** 어떤 회차가 정답/오답/보류였는지 목록만 보고도 스캔할 수 있다.

## 결정 (스파이크에서 개발자 확정, 2026-09-16)

R7 스파이크에서 `problem-detail.stories.tsx`(스파이크, 이후 삭제)에 5개 구조 후보를
실제 `MOCK_DETAILS`(3회차, 메모 포함) 위에 렌더해 비교:

| 안 | 설명 | 결과 |
|---|---|---|
| 1 | 현재 구조 + 색상 태그만 | 기각 |
| 2 | 세로 타임라인 (선+도트) | 기각 |
| 3 | 회차 카드 스택 | 기각 |
| 4 | 요약 우선 + 접이식 회차(아코디언) | 기각 |
| **5** | **좌우 분할 (회차 목록 + 상세 패널)** | **채택** |

기각 사유: 2는 시각적으로는 "히스토리"답지만 화면 폭을 세로로만 써서 회차가 많아지면
여전히 스크롤이 김(US-1 미해결). 3은 카드가 커서 한 화면에 2~3회차만 보임. 4는
아코디언 열고 닫는 상호작용이 "회차 비교"에는 비직관적.

**채택 — Option 5**: 왼쪽에 회차 번호 + 결과색 점(dot) 목록(좁은 컬럼), 오른쪽에 선택된
회차의 전체 상세(`AttemptItem` 그대로 재사용)를 보여주는 패널. 기본 선택 = 최신 회차.
회차 1개뿐이면 목록 없이 `AttemptItem` 단독 표시(기존 동작과 동일 — US-1이 애초에 해당 없음).
