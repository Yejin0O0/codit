# 프론트엔드 백엔드 API 연동 요구사항

## 개요

익스텐션 위젯과 익스텐션 페이지에서 현재 목 데이터로 동작하는 부분을 실제 백엔드 API와 연결한다.
모든 API 호출은 `authenticatedFetch`를 사용한다 (이슈 #60 요건).

---

## 사용자 시나리오

**시나리오 1 — 위젯에서 결과 기록 저장**

**Given** 사용자가 SWEA 문제를 풀고 결과 선택 → 태그 선택 → 메모 입력을 완료했다
**When** 저장 버튼을 클릭한다
**Then** 백엔드에 결과 기록이 저장되고 저장 완료 화면으로 전환된다

**시나리오 2 — 저장 실패 시 재시도**

**Given** 사용자가 저장 버튼을 눌렀으나 API 호출이 실패했다
**When** 토스트로 실패를 알리고 저장 버튼에 경고 아이콘이 표시된다
**Then** 사용자가 저장 버튼을 다시 클릭하면 API 요청을 재시도한다

**시나리오 3 — 위젯에서 태그 조회**

**Given** 사용자가 태그 선택 화면에 진입했다
**When** 화면이 로드된다
**Then** 백엔드에서 태그 목록을 조회해 표시한다 (현재 mockData 대체)

**시나리오 4 — 커스텀 태그 등록**

**Given** 사용자가 TagPicker에서 직접 태그를 입력하고 추가 버튼을 눌렀다
**When** 추가 버튼을 클릭한다
**Then** 백엔드에 태그를 등록하고 목록에 반영한다

**시나리오 5 — 히스토리 조회**

**Given** 사용자가 익스텐션 페이지를 열었다
**When** 히스토리 탭에 진입한다
**Then** 백엔드에서 문제 풀이 목록을 조회하고, 항목 클릭 시 상세 기록을 표시한다

---

## 경계 조건 및 엣지 케이스

- **저장 중 중복 제출 방지** — 저장 버튼에 스피너가 표시되는 동안 버튼을 비활성화한다
- **저장 실패** — 토스트로 즉시 알리고, 저장 버튼에 경고 아이콘을 유지한다. 버튼 텍스트는 변경하지 않는다. 재클릭 시 API 재시도
- **태그 조회 실패** — 에러 상태를 표시하고 재시도 가능하게 한다
- **히스토리 빈 목록** — "기록 없음" 상태를 표시한다
- **히스토리 조회 실패** — 에러 상태를 표시한다

---

## 에러 처리 방식

| 상황 | 처리 |
|------|------|
| 결과 기록 저장 실패 | shadcn 토스트 + 저장 버튼 경고 아이콘 유지, 재클릭 시 재시도 |
| 태그 조회/등록 실패 | 인라인 에러 표시 |
| 히스토리 조회 실패 | 인라인 에러 표시 |
| 인증 만료 (401) | `authenticatedFetch` 내부에서 자동 refresh 처리 |

## 이슈 분리 방침

| 이슈 | 범위 |
|------|------|
| 이슈 A | 위젯 — 결과 기록 저장 API 연동 |
| 이슈 B | 위젯 — 태그 조회/등록 API 연동 |
| 이슈 C | 익스텐션 페이지 — 문제 풀이 히스토리 조회 API 연동 (목록 + 상세) |

---

## Out of Scope (초안)

- 오프라인 저장 / 큐잉
- 저장 이력 로컬 캐싱
- 히스토리 필터링 / 검색
- 태그 삭제 / 수정

---

## 용어 정의

| 용어 | 정의 |
|------|------|
| 결과 기록 (Attempt) | 문제 풀이 1회의 결과 — 결과(CORRECT/WRONG/HOLD), 시간, 태그, 메모 포함 |
| 태그 (Tag) | 문제에 붙이는 알고리즘 유형 레이블. 코어 태그(서버 정의)와 커스텀 태그(사용자 정의)로 구분 |
| 히스토리 (Problem History) | 사용자가 풀었던 문제의 결과 기록 목록 |
| authenticatedFetch | 선제 refresh + 401 fallback이 내장된 인증 fetch 래퍼 (`src/lib/authenticatedFetch.ts`) |
