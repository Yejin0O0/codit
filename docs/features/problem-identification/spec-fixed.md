# problem-identification 요구사항

## 개요

사용자가 SWEA 문제 페이지에 접속하면, 페이지 URL의 쿼리 파라미터에서 문제를 식별하는 값(`contestProbId`)을 파싱해 백엔드에 저장하는 기능. 이후 타이머·태그·풀이 기록(Attempt) 등 다른 기능이 이 식별 결과(problem_id)를 기준으로 연결된다.

- **Primary User**: SWEA에서 문제를 푸는 사용자 본인
- **UI 진입점**: 브라우저 툴바의 익스텐션 아이콘을 사용자가 클릭해야 뜨는 팝업 (WXT `popup` entrypoint). 페이지 접속 시 자동으로 뜨는 오버레이 아님.

## 사용자 시나리오

**시나리오 A — 문제 페이지 최초 식별**

**Given** 사용자가 SWEA 문제 페이지(`contestProbId` 쿼리 파라미터 포함)에 접속했다
**When** 사용자가 익스텐션 아이콘을 클릭한다
**Then** 콘텐츠 스크립트가 URL에서 `contestProbId`를 파싱하고, JWT로 식별된 사용자·식별 시각·URL과 함께 백엔드에 저장한다

**시나리오 B — 같은 문제 페이지 새로고침/재방문**

**Given** 사용자가 이미 식별된 문제 페이지에서 새로고침하거나 다시 방문했다
**When** 콘텐츠 스크립트가 재실행되어 `problem_id`를 다시 파싱한다
**Then** `chrome.storage`에서 해당 `problem_id`로 진행 중인 Attempt가 있는지 확인하고, 있으면 재사용한다 (백엔드에 새로 저장하지 않음)

**시나리오 C — 문제 페이지가 아닌 곳에서 팝업 클릭**

**Given** 사용자가 `contestProbId` 파라미터가 없는 페이지(메인, 목록 등)에 있다
**When** 사용자가 익스텐션 아이콘을 클릭한다
**Then** 팝업에 "문제 페이지가 아닙니다" 안내를 표시한다 (에러가 아닌 정상적인 empty state)

## 경계 조건 및 엣지 케이스

- `contestProbId` 파라미터가 없는 페이지: 팝업 클릭 시 "문제 페이지가 아닙니다" 안내 표시. 파라미터가 없다고 해서 별도 에러로 취급하지 않음 (시나리오 C)
- 같은 문제 재방문/새로고침: `chrome.storage`에 저장된 진행 중 Attempt 존재 여부로 중복 식별(백엔드 재저장)을 방지 (시나리오 B)
- 인증: 이 이슈는 "요청 시점에 유효한 JWT가 존재한다"는 것을 전제로 구현한다. JWT 발급·검증 자체는 별도 팀원이 진행 중인 인증 이슈에 의존한다 (이 이슈는 그 결과물이 있다고 가정)

## 에러 처리 방식

백엔드 저장 API 호출이 실패하는 경우(네트워크 오류, 서버 오류, JWT 만료 등):

- 팝업에 에러 메시지와 **수동 재시도 버튼**을 표시한다 (방안 2 채택)
- 조용한 실패(방안 1)는 채택하지 않는다 — Codit의 핵심 가치가 정확한 풀이 통계이므로, 저장 실패를 사용자가 인지하지 못한 채 데이터가 유실되면 안 된다
- 백그라운드 자동 재시도(방안 3)는 이번 이슈 범위를 벗어나는 것으로 판단해 제외. 필요 시 향후 개선사항으로 `docs/improvements.md`에 기록한다

## Out of Scope (초안)

- 문제 제목(`title`)·난이도(`difficulty`) 자동 수집 — URL 파싱만으로 얻을 수 없고, 팝업 UI 특성상 표시할 필요 없다고 판단해 제외
- 태그 저장/선택 — 사용자가 직접 선택하는 별도 기능으로 다음 이슈에서 진행
- 대시보드 연동 — MVP 이후 가능성만 있고 현재 범위 아님
- 인증(JWT) 발급·검증 로직 자체 구현 — 별도 팀원이 진행 중인 이슈의 산출물에 의존
- 응답 시간·데이터 크기 등 성능 기준 — 아직 미정, 추후 결정
- 백엔드 저장 자동 재시도(백그라운드 큐, 방안 3) — 향후 개선사항 후보

## 용어 정의

| 용어 | 정의 |
|---|---|
| 문제 식별(Problem Identification) | SWEA 문제 페이지 URL의 `contestProbId` 쿼리 파라미터를 파싱해 사용자가 보고 있는 문제를 인식하는 동작 |
| `contestProbId` | SWEA 문제 페이지 URL에 포함된 쿼리 파라미터. 문제를 고유하게 식별하는 값 |
| Attempt(진행 중) | 아직 제출되지 않은, 현재 풀이 중인 시도. `chrome.storage`에 `problem_id` 기준으로 임시 보관되며, 새로고침/재방문 시 중복 식별을 막는 데 쓰인다 (제출 결과가 포함된 `shared-types`의 `Attempt`와는 별개 개념) |
| 식별 시각(identifiedAt) | 문제가 식별되어 백엔드에 저장된 시점의 타임스탬프 |
